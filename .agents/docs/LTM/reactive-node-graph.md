# Reactive node graph and GoX

The public packages are [reactive](../../../reactive/README.md), [ui](../../../ui/README.md) and [ui/gox](../../../ui/gox/README.md). Root [architecture](../../../ARCHITECTURE.md#reactive-node-graph) is canonical. Sources: journal entries "Reactive node graph and GoX native printer" and "Reactive example authored in GoX".

* GoX v0.3.3 (`508309b766d1cb47171b247a98b8db44e81c9146`) supplies typed cursor/printer jobs, not the application signal graph. Its MIT runtime dependency is direct; compiler/formatter code is not linked. Standard jobs are pooled: copy values and release once, without calling HTML output.
* `reactive.Graph` is synchronous and belongs to one application goroutine. Dynamic signal/memo reads replace dependencies on each evaluation. Memo equality suppresses dependent effects; pull stale memos before consumers to avoid diamond glitches. Batch writes are immediate and are not rolled back by an error.
* Effects own fresh run scopes. Dispose nested effects and cleanups before reruns; structural row/branch scopes must remain stable outside a rerunning effect's run scope. Factories execute untracked so incidental construction reads do not subscribe the list/conditional effect.
* `ui.Document` caches stable nodes and owns one active sink. `For` preserves keys and `Show` disposes hidden branches. Structural children can have sibling Go scopes (GoX jobs and embedded ranges), so node cleanup also disposes structural descendants. Never rely solely on scope nesting for node lifetime.
* Input bindings mirror native acknowledgements with `InputState.Accept`; only authoritative replacements call `Reset`. Stable node IDs preserve native entity/selection/composition across snapshots and keyed reorder. A plain Go state assertion cannot establish this; inspect native IDs, focus and selection, then type after reorder.
* Failed computations and runaways suppress settled sinks until recovery. Sink failures remain sticky without automatic mutation retries. Reject competing sinks before initial dispatch; shared document dirtiness cannot safely feed two independent sinks.
* The wire is unchanged: full protobuf snapshots, bounded by existing message/depth/count limits. Fine-grained binding execution does not mean native incremental protocol patches.
* Example authoring now uses `examples/reactiveapp/view.gox`, with generated `view.x.go`. Keep signal state and persistent `Show`/`For` scope factories in Go; factories build row/branch template components within their supplied owner. Plain template expressions and native GoX if/for run at construction, so preserve reactive text accessors explicitly.
* `make fmt-reactive` formats source then generates and gofmts Go output. `make check-reactive-generated` regenerates in scratch space and compares bytes without mutating checked-in files. The GoX CLI needs the runtime import explicitly in template source. Compiler and runtime versions match v0.3.3; checksum-pinned prebuilt CLI archives avoid adding compiler/formatter dependencies to app builds. Do not hand-edit generated files.
* Generation is maintained in per-example `generate.go` files. Make and `tools/check_gox_generated.py` execute `go generate`, including the directive-owned gofmt step. The checker copies the directives and preserves their directory depth in an isolated package with a pinned tool link. `make generate-gox` / `check-gox-generated` cover both the reactive example and `examples/counter-gox/app`.

`make reactive` runs the interactive consumer. `go test -race ./reactive ./ui ./ui/gox` tests dependency/ownership/error/input/printer failure classes without native archives. `e2e/scenarios/reactive.star` verifies one template build, selective batching, memo equality, branch disposal and persistent native inputs. The native suite uses synthetic GPUI events, not OS IME or pixel assertions.
