# Go package structure

Canonical ownership and dependency rules are in [architecture](../../../ARCHITECTURE.md); public migration instructions are in [README](../../../README.md#packages-and-migration). Source: journal entry "Go package structure refactor".

* `scene` owns protobuf snapshot builders/styles/input versions. `client` owns transport/session/window/event/resource/model behavior and depends on `scene`. Resource ownership stays in the client; `scene.Image` receives a copied opaque handle.
* `host` owns startup-thread locking, Sable/cgo, platform loops and shutdown. `gpui.Run` forwards to it. Lower-level libraries must import canonical packages directly so native build tags do not bring startup side effects into reusable graphs.
* Root `gpui` aliases canonical types and wraps constructors/Run. Methods live on the canonical types. This preserves interoperability without duplicate state or a dependency back from implementations to the facade. Reflection reports the canonical defining package.
* Application values have a second alias layer: `scene` exposes styles/geometry/drawing/interaction/accessibility and input acknowledgement values; `client` exposes event payloads/kinds and service values. These remain true aliases of protobuf messages/enums, so reflection retains generated identities. Concise enum constants keep `.Enum()` methods, and `scene.Ptr[T]` preserves optional zero/false presence. Generic examples use public values rather than generated bindings/helpers; `examples_api_test.go` guards this ergonomic contract.
* `reactive` remains independent of GPUI. `ui` depends on `reactive`, `scene` and `client`; `ui/gox` adds only the GoX runtime. Keep graph algorithms and mounting together until a further boundary has a concrete consumer.
* `uitest` owns targets, locators/assertions, scenarios and worker reports. `uitest/gpui` owns `Application`, `Factory`, `NativeTarget` and `NewNativeTarget`; callers migrate these imports explicitly. A root forwarding constructor would create an import cycle because the driver consumes `uitest` contracts.
* `uitest/starlark` owns scripting. Deprecated `e2e` aliases/forwards `Harness`, `New` and `Check`; scenarios/testdata stay under `e2e/`. Runner factories adapt example `*App` values. Application presentation does not import testing interfaces.
* Existing private client tests moved to `client`, snapshot ownership tests to `scene`, Sable integration to `host`, and interpreter tests to `uitest/starlark`. The integration test uses a test-only raw request helper to observe Rust stale-handle rejection without exporting an extra client method.

`TestPackageArchitecture` checks actual transitive imports with native/automation tags selected. The scratch overlay negative control added a blank root-facade import to `ui`; compilation succeeded and the dependency test failed on the resulting native-startup path. No production source was altered by that control. `TestCompatibilityFacadeInteroperatesWithCanonicalPackages` exercises aliases, resource image construction, snapshot copying and typed errors through a fake transport. Native suite and Sable integration evidence remain separate from this structural proof.

The refactor stays within one Go module. Protocol/schema/generated paths, Rust crate boundaries, pinned runtime dependencies, editor API and GPL opt-in remain unchanged. GoX component construction accepts `gox.Elem`. The subsequent reactive-example rewrite adds `.gox` source and a pinned standalone generation workflow; compiler tooling remains separate from package ownership and application imports.
